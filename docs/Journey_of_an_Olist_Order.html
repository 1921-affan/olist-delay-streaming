    Words used on this page

    Topic
    A named stream of messages in Kafka. We use 4: orders, shipment-events, delay-predictions and alerts.
    Partition (P0, P1, P2)
    A topic is split into lanes so three scorer copies can work in parallel. The alerts topic has one partition.
    Key
    The order_id sent with each message. CRC32(key) mod 3 picks the partition, so all four events of an order use the same partition number and stay in order.
    Offset · commit
    A message's position in its partition. Commit = save "finished up to here". We commit only after the results are safely stored.
    Consumer group
    Copies of a service sharing topics; each partition is read by exactly one copy. The range assignor gives one copy the same partition number of both input topics.
    Raw score · P(late)
    Raw score is the XGBoost output and is compared with the threshold (Model 1: 0.7493, Model 3: 0.7364). P(late) is the calibrated probability shown on dashboards.
    Severity
    HIGH = model alert at handoff, or model alert + R2 · MEDIUM = Model 1 alert alone, or R2 alone · no alert otherwise. R8 surge alerts are HIGH.
    Rules R1–R9
    R1 slow approval, R2 missed shipping deadline, R5 tight promise, R6 long route, R7 unreliable seller (scorer); R8 region surge (aggregator); R9 = model alert. R3/R4 need a timer.
    Idempotent write
    Primary keys with ON CONFLICT: a re-delivered message cannot create a second row.
    Tumbling window
    One simulated day per customer state and per seller, by event time (when it happened in 2018), not arrival time.
    Watermark
    Newest event time seen − 6 h grace. A day window closes when the watermark passes its end; events up to 7 days late still update it.
    rejected_events
    Table where broken messages are kept with the reason, topic, partition and offset, so the stream never stops for a bad message.
